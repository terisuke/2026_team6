# ADR-005: スワイプ式画像選択ゲームへのリデザイン

## ステータス
承認済み (2026-03-28)

## コンテキスト
Real You は5軸の性格診断アプリで、3つのインタラクティブゲーム（利用規約、ヘルプデスク、グループチャット）を通じてユーザーの行動データを収集し、性格スコアを算出していた。

### 問題点
1. **プレイ時間が長すぎる**: 3ゲーム完走に10分以上かかり、離脱率が高い
2. **Expressバックエンドの冗長性**: SupabaseのCRUDをラップしているだけで、Express層の付加価値が低い
3. **Gemini API依存**: Game 2のAIチャットがGemini APIに依存しており、レイテンシとコストの問題
4. **科学的根拠の弱さ**: 利用規約スクロールやチャット入力からの性格推定は心理学的根拠が薄い

## 決定
3ゲーム構成を**スワイプ式画像選択1ゲーム（10ラウンド）**にリデザインする。

### アーキテクチャ変更
| 項目 | Before | After |
|------|--------|-------|
| ゲーム数 | 3（利用規約/ヘルプデスク/グループチャット） | 1（スワイプ画像選択） |
| プレイ時間 | 10分以上 | 1〜3分 |
| バックエンド | Express + Supabase | Supabase直接 + Next.js Route Handler |
| AI依存 | Gemini 2.0 Flash Lite | なし |
| データ収集 | クリック/タイピング/音声 | マウス軌跡 + スワイプ方向 |
| 自己申告 | 5問 | 3問 |
| 画像データ | なし | OASIS感情画像データセット（28枚） |

### 新フロー
```
/ (トップ) → /diagnosis (MBTI + 3問) → /game (スワイプ10R) → /result (2タブ)
```

### スコアリング方式
マウス軌跡から11メトリクス（SwipeMetrics）を抽出し、5軸にマッピング:
- **慎重さ**: 迷い時間 + ホバー時間 + 方向転換 + 軌道逸脱
- **冷静さ**: ブレ少なさ + 滑らかさ + 速度安定性 + ストレス耐性
- **論理性**: 選択一貫性 + 方向転換少なさ + 軌道直進性
- **協調性**: 社会的画像の右スワイプ率 + ホバー時間比
- **積極性**: スワイプ速度 + 決断速度 + 初動速度 + タイムアウト少なさ

### 画像選定
OASIS (Open Affective Standardized Image Set) から14ペア（28枚）を選定:
- 秩序 vs 自由（4ペア）→ 慎重さ・論理性
- 静寂 vs 活気（4ペア）→ 冷静さ・積極性
- 集団 vs 個人（3ペア）→ 協調性
- 抽象 vs 具象（3ペア）→ 論理性・冷静さ

## 根拠
1. **心理学的エビデンス**: マウス軌跡分析は意思決定研究で広く使われる手法（Freeman & Ambady, 2010; Kieslich & Henninger, 2017）
2. **OASIS画像**: 標準化された感情価・覚醒度を持つ研究用画像セット（Kurdi et al., 2017）
3. **UX改善**: 1〜3分で完結するスワイプUIはモバイルネイティブで直感的
4. **インフラ簡素化**: Express層の削除でデプロイ・運用コストが半減

## 影響
- Express backendの全削除
- Gemini API依存の完全排除
- フロントエンド主導のアーキテクチャ（Supabase Client SDK直接利用）
- ゲームロジックがフロントエンドに集約

## 実装計画
5 Wave構成で段階的に移行:
1. Wave 1: 基盤整備（型定義、DB、Gemini削除、画像配置）— 完了
2. Wave 2: データ層・スコアリングエンジン移植
3. Wave 3: スワイプUI・マウストラッキング
4. Wave 4: 診断フロー・結果表示リデザイン
5. Wave 5: ルーティング統合・旧コード削除・統合テスト

## 代替案
1. **既存3ゲームの改善**: 却下。根本的にプレイ時間が長い問題は解決しない
2. **2ゲームに削減**: 却下。ゲーム間の遷移コストが残る
3. **バックエンド維持**: 却下。Supabase直接アクセスで十分な機能が実現可能
